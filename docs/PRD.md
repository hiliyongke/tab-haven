## 1. 产品概述

### 1.1 背景与机会

**标签过载是浏览器用户的持久痛点。** 研究者、开发者、重度阅读者的浏览器常年保持数十至数百个标签页；标签堆积导致找不到页面、内存吃紧、误关损失现场。这一痛点在过去十年从未被真正解决。

**竞品格局高度分化，无人通吃。** 现有标签管理产品各占一个心智山头，且各有结构性短板：

- OneTab（约 200 万用户）以"一键收纳"取胜，但只提供平面列表，无组织结构，数据丢失口碑长期存在；
- Session Buddy（约 4.8/5 评分）是会话恢复之王，但 UI 老派、迭代缓慢；
- Workona（订阅 $7/月）与 Toby（免费版限 60 张卡片、订阅 $4.5/月起）提供工作区与视觉收集箱，但深度绑定云账号，存在数据锁定与隐私顾虑；
- Tab Wrangler、Auto Tab Discard 等只解决自动清理或休眠单一问题。

**浏览器原生功能正在挤压扩展的基本盘。** Chrome 已于 2026 年 4 月官方上线原生垂直标签、标签搜索（Ctrl+Shift+A）与内存节省程序；Edge 提供垂直标签栏与睡眠标签；Opera One 提供标签岛屿与垂直标签。单纯"把标签列出来"或"看看内存占用"的扩展已无生存空间。

**结论：扩展的护城河必须建在原生功能做不好的地方**——组织规则（多级域名归组、归档）、会话管理（快照与恢复）、键盘流与可撤销的批量操作，以及**本地优先的隐私承诺**（对抗云服务竞品的账号依赖）。TabHaven 的定位正是把上述五项护城河整合进一个免费、无账号、数据不离设备的产品。

### 1.2 产品定位与叙事

**一句话定位**：

> 一个本地优先、无账号无云端的标签工作台：把散乱的标签组织成有秩序的空间，并保证你永远找得回来。

"组织"对应智能分组、固定空间、归档中心三大能力域；"找得回来"对应搜索键盘流、会话快照、多层撤销三大安全网能力域。

**差异化卖点（对外传播优先级排序）**：

1. **数据不离设备** —— 信任基石。无后端、无账号、无遥测、零上传，直接回应 Workona/Toby 用户的账号疲劳与隐私顾虑。
2. **组织智能** —— 多级域名自动归组、可配置聚合规则、归档中心，打击 OneTab 式平面列表的"找不到"问题。
3. **会话安全网** —— 命名快照、自动保存、多层撤销，对标 Session Buddy 的最强刚需，但以现代交互交付。
4. **键盘流与可撤销批量** —— 模糊搜索、快捷键体系、多选批量操作且每一步可撤销，原生 Ctrl+Shift+A 做不到的组织化操作。
5. **全 Chromium 降级兼容** —— Chrome/Edge 首发主打侧边栏形态，Brave/Opera/Vivaldi 等以特性检测提供降级形态，覆盖主流国际 Chromium 浏览器。

### 1.3 目标与非目标

**目标**：成为 Chromium 用户"本地优先的标签工作台"默认选择——一个扩展同时解决组织、找回、恢复、省内存四类问题。

**非目标（Non-Goals）**，每条附不做的原因：

| 非目标 | 原因 |
| --- | --- |
| 不做自有云服务与账号体系 | 与"数据不离设备"的宪法级原则直接冲突；也是与云竞品的差异化本身 |
| 不做团队协作/共享空间 | 赛道不同；协作必然引入账号与后端 |
| 不替换新标签页 | 赛道拥挤（Toby/BoTab），且与本产品"侧边栏工作台"心智不符 |
| 不做广告、推荐位与第三方统计 | 违背隐私承诺；产品完全免费且无变现依赖 |
| 不做内容理解类能力（读取页面正文、AI 摘要） | 权限最小化原则；"标签管理"边界之外 |
| V2.0 前不承诺 Firefox | Firefox 需走独立的 sidebar 适配路线，纳入会稀释主线（国产浏览器同理，见 OQ-6） |

### 1.4 产品原则

**五条既有行为原则**（其完整行为规格见附录 C）：

1. 默认只管理当前窗口，不打扰其他窗口；
2. 操作保持可撤销，避免静默改变用户标签结构；
3. 不修改浏览器原生标签组中语义不明确或不可恢复的状态；
4. 界面克制，非必要信息按需出现；
5. 新权限、新网络请求、新持久化数据必须同步更新 README 与隐私说明。

**本产品新增的三条宪法级原则**：

6. **数据不离设备**：所有用户数据仅存于浏览器本地存储；跨设备仅借助浏览器自身的同步通道（chrome.storage.sync）或用户主动导出的文件；永不自建网络上报通道。
7. **降级而非拒绝**：在不支持侧边栏的浏览器上，以特性检测提供弹窗快速切换器、全标签页或独立弹出窗口等替代形态，而非拒绝运行。
8. **默认克制、能力按需开启**：一切自动化能力（闲置归档、自动分组、自动休眠）默认关闭，由用户显式开启且每一条规则可单独停用、每一次自动操作可撤销。

## 2. 用户与场景

### 2.1 目标用户画像

**画像一：多项目并行的知识工作者**

- **身份**：研究员、咨询顾问、产品经理；同时推进 3-5 个项目，浏览器常年保持 50-200 个标签。
- **典型场景**：上午写 A 项目方案需要 10 个参考页，下午切到 B 项目调研又要开 15 个；项目切换时上一项目的标签还挂在标签栏里"怕关了找不回来"。
- **痛点**：项目上下文混在一起；为标签管理付 $7/月不甘心；云产品的账号注册与数据锁定令人抗拒。
- **当前替代方案**：Workona/Toby 的免费额度，或干脆开多个浏览器窗口加书签文件夹硬扛。
- **为何选 TabHaven**：固定空间与归档中心天然按项目收纳；数据随时导出为开放格式；零费用零账号。
- **流失触发点**：数据导出受限或格式不开放；空间概念过度复杂（超过三层结构即抱怨"比我的项目还乱"）。
- **首席用户故事归属域**：D4 固定与空间、D3 智能分组、D9 数据。

**画像二：现场保护者**

- **身份**：学生、分析师、写作者；习惯把标签当"工作记忆"，攒着不关。
- **典型场景**：查资料开到 60+ 标签，浏览器崩溃或手滑关掉窗口，两小时的线索整理瞬间蒸发。
- **痛点**：对"恢复"有强烈焦虑；原生"最近关闭"只能找回最后几个标签，且不保留分组关系。
- **当前替代方案**：Session Buddy 或 Tab Session Manager，忍受老派 UI。
- **为何选 TabHaven**：命名快照 + 关窗自动保存 + 多层撤销三重安全网；恢复时标签的固定状态与分组关系一并找回。
- **流失触发点**：**恢复失败一次即流失**——可靠性是此画像的生死线；自动保存静默失效也不可接受。
- **首席用户故事归属域**：D5 会话管理、D8 治理与安全网、D7 归档中心。

**画像三：内存节俭者**

- **身份**：使用老设备或低配电脑的重度网页阅读者；标签开多即卡顿。
- **典型场景**：同时开着 30 个技术文档页，风扇起飞、输入延迟明显；原生内存节省程序不可控，把自己正要看的页面也冻结了。
- **痛点**：需要"冻结不看的、保住正在用的"，但原生功能没有白名单粒度，也没有状态可视化。
- **当前替代方案**：Auto Tab Discard 或干脆手动关标签再从历史里找。
- **为何选 TabHaven**：手动休眠/唤醒、按固定条目与域名设白名单、休眠状态在侧边栏一目了然；与原生内存节省程序互补不冲突。
- **流失触发点**：**休眠导致表单内容丢失即流失**——只休眠可安全丢弃的页面是硬约束；休眠唤醒速度慢于直接打开新标签也会被弃用。
- **首席用户故事归属域**：D6 休眠与资源优化。

**画像四：键盘优先的效率玩家**

- **身份**：开发者、极客；信奉全键盘操作，鼠标是摩擦。
- **典型场景**：想切到某个标签，按两下快捷键、敲几个字母、回车，全程不超过两秒；对需要鼠标悬停才能出现的按钮零容忍。
- **痛点**：原生 Ctrl+Shift+A 只搜当前窗口且无组织能力；多数扩展的键盘支持停留在"能按"而非"跟手"。
- **当前替代方案**：Tabli、Tab Manager Plus，或浏览器自带搜索。
- **为何选 TabHaven**：模糊搜索 + 上下键选择 + 回车切换的完整键盘流；批量操作也有快捷键入口。
- **流失触发点**：快捷键有一步不跟手（焦点丢失、延迟、按键冲突）就弃用。
- **首席用户故事归属域**：D2 搜索与键盘流、D1 视图与导航。

### 2.2 核心任务（JTBD）与用户旅程

**JTBD（Job-to-be-Done）陈述**：

1. 当我同时推进多个项目时，我想把每个项目的常用页面各自收纳，以便切换项目时立刻进入状态。（画像一）
2. 当我攒了几十个研究标签时，我想按网站自动成组而不是手动整理，以便同类页面一眼看清、一键处理。（画像一/二）
3. 当我浏览器崩溃或误关窗口时，我想完整找回刚才的全部标签及其分组关系，以便工作现场零损失。（画像二）
4. 当我设备卡顿时，我想把暂时不看的标签冻结而保留在原位，以便释放内存又不怕丢页面。（画像三）
5. 当我想切到某个页面时，我想敲几个字母就直达，以便全程不离键盘。（画像四）
6. 当我要清理标签时，我想先批量选中再统一处理且能反悔，以便放心大胆地整理。（全体）
7. 当我换电脑或换浏览器时，我想把全部固定集合与归档打包带走，以便不被任何产品锁定。（画像一）

**新用户旅程（指导后续引导设计）**：

安装 → 打开侧边栏看到当前窗口标签列表（零配置可用，对应 JTBD 无）→ 数天后同站点标签增多，发现自动成组（JTBD 2，首次"啊哈"时刻）→ 把高频页面拖入顶部固定区（JTBD 1 起点）→ 某次误关后用撤销找回（JTBD 6，信任建立时刻）→ 开启自动保存与归档（JTBD 3，深度用户转化时刻）。

### 2.3 竞品参照与差异化定位

完整竞品对比矩阵见**附录 D**。正文结论：TabHaven 卡位于 OneTab 的极简心智、Session Buddy 的会话刚需、Workona 的组织能力三者的交集，同时做到全部本地化、免费、无账号——这一格在当前市场中为空白。

浏览器原生功能（Chrome 垂直标签/标签搜索/内存节省、Edge 垂直标签/睡眠标签）被视为"基础盘参照"而非竞品：TabHaven 不与原生功能重复（不在侧边栏重复做内存看板），专注原生做不好的组织、会话、规则与键盘流。

### 3.1 D1 视图与导航

#### FR-D1.1 多选与批量操作 [P0｜V1.0]

- **用户故事**：作为键盘优先的效率玩家（也惠及全部画像），我想用 Shift 连选、Ctrl/Cmd 点选选中多个标签后统一关闭、固定、静音或移动，以便整理几十个标签时不必逐个操作。
- **描述**：侧边栏进入"选择模式"后（工具栏按钮或快捷键进入），标签行呈现复选态：单击选中/取消，Shift 单击范围连选，Ctrl/Cmd 单击追加点选；支持 Ctrl/Cmd+A 全选当前分组或全部。选中集悬浮操作条提供：批量关闭、批量固定、批量静音、批量移入固定文件夹、批量移动到指定分组。批量关闭必须走统一关闭通道并进入多层撤销栈（FR-D8.1）；批量移入固定文件夹沿用"同一 URL 全局唯一"的基线规则。Esc 退出选择模式并清空选中集。
- **验收标准**：
  - Given 30 个标签的窗口，When Shift 连选第 3-10 个标签后点击批量关闭，Then 8 个标签全部关闭且状态提示提供撤销入口，一次撤销恢复全部 8 个；
  - Given 选中含固定标签的集合，When 批量关闭，Then 固定标签跳过关闭（与基线清理策略一致），提示中说明"已跳过 N 个固定标签"；
  - Given 选中 5 个标签，When 批量移入固定文件夹 X，Then X 中新增 5 条且其中与他处重复的 URL 被全局去重；
  - Given 选择模式中发生标签外部变化（其他标签关闭），When 选中集中某标签消失，Then 自动从选中集移除，不影响其余选中。
- **依赖与风险**：依赖 FR-D8.1（多层撤销）；与拖拽交互的事件冲突需在交互设计时消解。
- **降级形态**：弹窗形态不提供多选（空间不足）；全标签页与独立弹出窗口完整支持。

#### FR-D1.2 多窗口鸟瞰视图 [P2｜V2.0]

- **用户故事**：作为多项目并行的知识工作者，我想在需要时鸟瞰全部窗口的标签并跨窗口移动，以便集中整理。
- **描述**：默认关闭的可选开关（默认值即产品原则 1 的体现）；开启后侧边栏增加"全部窗口"分组视图，支持按窗口折叠、跨窗口拖动标签。开关状态持久化，并在开启时以一次性提示声明"已离开仅当前窗口模式"。
- **验收标准**：
  - Given 开关默认关闭，When 首次安装，Then 侧边栏仅显示当前窗口（与基线一致）；
  - Given 开启鸟瞰，When 将标签从窗口 1 拖入窗口 2 的分组，Then 标签移动且两窗口的侧边栏视图同步更新；
  - Given 关闭开关，When 重新打开侧边栏，Then 恢复仅当前窗口视图。
- **依赖与风险**：无硬依赖；注意与"只管当前窗口"原则的边界以开关默认值化解。
- **降级形态**：全标签页形态完整支持（这也是鸟瞰的最佳载体）；弹窗形态只读展示。

### 3.2 D2 搜索与键盘流

#### FR-D2.1 搜索增强 [P0｜V1.0]（变更：替代基线子串搜索）

- **用户故事**：作为键盘优先的效率玩家，我想敲标题或域名的前几个字母甚至首字母缩写就命中目标，并用上下键加回车完成切换，以便两秒内直达任意标签。
- **描述**：在基线"标题+URL 子串匹配、仅当前窗口"之上升级：①支持拼音首字母与首字母缩写的模糊匹配（如输入 gh 命中 github.com）；②命中部分高亮；③结果列表支持 ↑/↓ 选择、Enter 切换、Esc 退出；④结果按"当前激活 > 最近使用 > 其余"排序；⑤仍保持仅当前窗口范围（与原则 1 一致）。结果为空时给出"试试更短的关键词"引导。
- **验收标准**：
  - Given 窗口含标题"GitHub · 示例"的标签，When 输入 gt，Then 该标签命中且"GitHub"中 G、域名中 t 对应字符高亮；
  - Given 搜索结果 5 条，When 按 ↓ 三次后 Enter，Then 第 4 条对应标签被激活且搜索框关闭；
  - Given 输入无结果关键词，When 继续输入至更短前缀，Then 结果实时刷新且无卡顿（见第 5 章性能指标）；
  - Given 按 Esc，Then 搜索关闭且焦点返回标签列表。
- **依赖与风险**：拼音匹配在中英双语下的行为需在交互设计时定义（英文界面下仍支持拼音）。
- **降级形态**：弹窗形态即"快速切换器"，本条为其核心能力；全页与独立弹出窗口完整支持。

#### FR-D2.2 快捷键体系 [P0｜V1.0]

- **用户故事**：作为键盘优先的效率玩家，我想通过浏览器级快捷键打开面板、聚焦搜索、切换分组，以便手不离键盘完成高频操作。
- **描述**：通过浏览器原生 commands 机制注册全局快捷键（用户可在浏览器设置中自定义按键）：①打开/聚焦侧边栏；②聚焦搜索框（等价 ⌘K 并向上兼容）；③折叠/展开当前标签所在分组；④进入/退出选择模式（配合 FR-D1.1）；⑤全选（配合 FR-D1.1）。默认按键遵循浏览器规范且不与常用快捷键冲突；所有快捷键在帮助面板中列出并可点击跳转浏览器的快捷键设置页。
- **验收标准**：
  - Given 任意网页焦点，When 按下"打开面板"快捷键，Then 侧边栏打开或聚焦；
  - Given 侧边栏打开，When 按"聚焦搜索"，Then 焦点进入搜索框且全文选中；
  - Given 帮助面板，When 查看，Then 全部已注册快捷键与其中文说明一一列出；
  - Given 用户在浏览器设置中修改默认按键，When 重启浏览器，Then 新按键生效且帮助面板同步展示。
- **依赖与风险**：新增 commands 权限（附录 A）；不同浏览器对命令数量上限不同（Chrome 为 4+2 建议，超出的快捷键以面板内快捷键实现）。
- **降级形态**：弹窗形态天然以快捷键唤起；面板内快捷键（非 commands）在所有形态可用。

### 3.3 D3 智能分组

#### FR-D3.1 多级域名归组 [P0｜V1.0]（变更：升级基线网站聚合）

- **用户故事**：作为多项目并行的知识工作者，我想让同一公司/平台旗下多个子域的标签归为一组（如 cloud.tencent.com 与 news.tencent.com 归入 tencent.com），以便按"站点主体"而非"精确域名"聚合同一来源的页面。
- **描述**：在基线域名归一化（去 www、托管公共后缀取三级、国家二级域、localhost 带端口）之上增加"注册域归组层级"：默认按注册域（eTLD+1）聚合子域；用户可对单个分组调整归组层级（收紧到精确子域或放宽到注册域），调整结果持久化。基线的全部既有规则（托管域、国家域、本地端口）保持不变。
- **验收标准**：
  - Given 窗口含 cloud.tencent.com、news.tencent.com 各 1 个标签，When 两标签均未固定未分组，Then 显示为"tencent.com"分组且组内标注子域；
  - Given 用户将某分组收紧为精确子域，When 新开同注册域其他子域标签，Then 不并入该分组；
  - Given github.io 等托管域下的标签，When 归组，Then 仍按基线规则取三级（user.github.io）而非放宽到 github.io；
  - Given localhost:3000 与 localhost:8080 各一标签，When 归组，Then 仍分属不同分组（基线行为不回归）。
- **依赖与风险**：公共后缀规则随时间变化，需随产品更新维护；层级调整的交互需克制（右键菜单入口，不新增界面层级）。
- **降级形态**：全形态支持（纯数据层能力）。

#### FR-D3.2 聚合阈值可配置 [P1｜V1.2]

- **用户故事**：作为现场保护者，我想把"同域名达到几个标签才聚合"从固定 2 调为 3 或 4，以便标签不多时不产生过多小分组。
- **描述**：设置项提供 2-5 的阈值调节，默认 2（与基线一致）；阈值变化即时重渲染且不影响已有的手动移出记录。
- **验收标准**：
  - Given 阈值设为 3，When 同域名第 2 个标签打开，Then 不聚合；第 3 个打开，Then 三标签聚合为组；
  - Given 修改阈值，When 已被手动移出的标签重新聚合判定，Then 其手动移出状态保留。
- **依赖与风险**：无。
- **降级形态**：全形态支持；弹窗形态在设置入口（全页）中调整。

#### FR-D3.3 分组折叠状态持久化 [P0｜V1.0]（变更：修复基线会话级丢失）

- **用户故事**：作为现场保护者，我想昨天折叠的网站分组今天重启浏览器后仍然折叠，以便回到熟悉的现场。
- **描述**：基线中网站分组的折叠状态仅内存态（重启即失），本条将其持久化到本地存储；原生标签组的折叠状态仍完全由浏览器管理（基线原则 3，不纳入持久化范围）。
- **验收标准**：
  - Given 折叠某网站分组后完全退出并重启浏览器，When 侧边栏打开，Then 该分组仍为折叠；
  - Given 分组因标签清空而消失后再次出现，When 查看折叠状态，Then 沿用此前的折叠偏好；
  - Given 原生标签组折叠，When 重启浏览器，Then 其状态与浏览器自身行为一致（本产品不干预）。
- **依赖与风险**：无。
- **降级形态**：全形态支持。

### 3.4 D4 固定与空间

#### FR-D4.1 固定文件夹排序 [P0｜V1.0]（补齐基线局限）

- **用户故事**：作为多项目并行的知识工作者，我想拖动调整固定空间中文件夹的先后顺序，以便最常用的项目排在最上面。
- **描述**：与基线"文件夹内条目排序"对齐，增加文件夹级拖动排序；排序持久化；拖动时呈现与条目排序一致的上/下半区插入指示线。
- **验收标准**：
  - Given 3 个文件夹，When 将第 3 个拖至第 1 位，Then 顺序更新且重启后保持；
  - Given 拖动经过某文件夹上半区，When 悬停，Then 显示"插入到其上方"指示线。
- **依赖与风险**：无。
- **降级形态**：全页与独立弹出窗口支持；弹窗形态不展示固定空间。

#### FR-D4.2 多空间切换 [P2｜V2.0]

- **用户故事**：作为多项目并行的知识工作者，我想为不同项目维护多套各自独立的固定集合与归组规则并在其间一键切换，以便浏览器变成随项目切换的工作台。
- **描述**：将基线"固定空间"升级为"空间"集合：每空间拥有独立的固定文件夹、永久固定图标子集与域名归组层级偏好；顶部提供空间切换器（名称 + 快捷键循环切换）；"默认空间"即现有全部数据的容器，升级后零迁移成本。空间的窗口语义（一空间绑定一个窗口，还是空间为全局切换的档案）为**开放问题 OQ-3**，须在 V2.0 开工前决策。
- **验收标准**：
  - Given 从默认空间新建空间"项目 B"，When 切换至项目 B，Then 固定区与固定空间仅显示项目 B 的内容，临时标签区不受影响；
  - Given 切换空间，When 向固定区拖入标签，Then 归属当前空间；
  - Given 删除空间（二次确认），When 确认，Then 仅删除该空间的固定集合，其他空间与临时标签不受影响。
- **依赖与风险**：OQ-3 未决前不得开工；空间数量与存储占用需设上限提示；与"数据不离设备"原则无冲突（全部本地）。
- **降级形态**：全页与独立弹出窗口支持；弹窗形态以空间名下拉切换。

### 3.5 D5 会话管理

#### FR-D5.1 手动快照与恢复 [P1｜V1.1]

- **用户故事**：作为现场保护者，我想把当前窗口的全部标签保存为一个命名快照并在之后一键恢复，以便浏览器崩溃、误关或隔天回来时完整找回现场。
- **描述**：底部工具区提供"保存快照"；快照记录当前窗口全部标签的 URL、标题、固定状态、静音状态、分组归属（原生组按组名还原，组不存在时重建；虚拟分组按归组规则自然还原）。保存时要求命名，提供默认名"快照 · M月d日 HH:mm"。快照列表支持重命名、删除、恢复。恢复语义为**加法**：仅新建缺失标签，不关闭现有标签（需要"先清空再恢复"时配合 FR-D1.1 批量关闭）；恢复出的标签自动豁免重复复用（继承基线豁免机制），避免恢复的标签被立即合并关闭。快照仅存本地。
- **验收标准**：
  - Given 窗口含 2 个固定标签、2 个原生组（共 8 标签）、40 个普通标签，When 保存快照后关闭 10 个标签再恢复，Then 10 个标签按原分组关系找回，其余 42 个不重复出现；
  - Given 恢复出的标签与现有标签 URL 相同，When 恢复完成，Then 不被自动复用机制关闭；
  - Given 恢复时某原生组已被删除，When 恢复，Then 按组名重建组并放入标签；
  - Given 快照列表，When 点击恢复，Then 全程无任何现有标签被关闭；
  - Given 新增快照数据类型，When 发布，Then README 与隐私说明已同步更新。
- **依赖与风险**：依赖基线豁免机制的稳定；快照数量需设本地存储占用提示（超限时引导导出归档）。
- **降级形态**：全页与独立弹出窗口完整支持（会话管理是全页形态的核心场景）；弹窗形态仅提供"快速保存"入口。

#### FR-D5.2 自动保存 [P1｜V1.2]

- **用户故事**：作为现场保护者，我想让产品在定时与关窗时自动保存快照，以便即使忘了手动保存也有兜底。
- **描述**：默认关闭（原则 8），开启后：①定时自动快照（最小检查间隔受浏览器定时机制约束，默认值见 OQ-5）；②窗口关闭时自动快照；③自动快照按"保留最近 N 份"滚动覆盖（N 默认值见 OQ-5），自动快照不占用用户命名快照的列表视觉重心（收纳在"自动"分区）。设置页明示"自动保存依赖浏览器后台机制，不保证任意时刻都有一份最新快照；重要现场请手动保存"。
- **验收标准**：
  - Given 开启自动保存，When 关闭一个含 20 标签的窗口，Then 自动快照生成且可从"自动"分区恢复全部 20 标签；
  - Given 自动快照已达保留上限，When 新一份生成，Then 最旧一份被覆盖、命名快照不受影响；
  - Given 未开启自动保存（默认），When 关窗，Then 不产生任何快照；
  - Given 设置页，When 查看，Then 可见到关于浏览器后台机制的能力边界说明。
- **依赖与风险**：浏览器后台定时机制（MV3 环境）不保证精确触发——产品明示边界而非静默承诺；新增可选 alarms 权限（附录 A）。
- **降级形态**：全页与独立弹出窗口支持；弹窗形态仅开关入口。

#### FR-D5.3 崩溃恢复入口 [P2｜V2.0]

- **用户故事**：作为现场保护者，我想在浏览器异常退出后重新打开时收到"恢复上次现场"的引导，以便崩溃损失降为零。
- **描述**：检测到上次会话异常退出（非用户正常关闭）且存在自动快照时，侧边栏顶部出现一次性引导条"检测到异常退出，可恢复 M 月 d 日的现场"；用户可选择恢复或忽略（忽略后本次不再提示）。判定标准以自动快照的存在性与浏览器会话恢复状态为依据，不做任何额外后台记录。
- **验收标准**：
  - Given 上次会话异常退出且存在自动快照，When 打开侧边栏，Then 出现引导条且仅出现一次；
  - Given 用户点击忽略，When 再次打开侧边栏，Then 不再提示；
  - Given 正常退出，When 打开侧边栏，Then 无引导条。
- **依赖与风险**：依赖 FR-D5.2；异常退出的判定精度有限，宁漏勿扰。
- **降级形态**：全形态支持（引导条形式轻量）。

### 3.6 D6 休眠与资源优化

#### FR-D6.1 手动休眠与唤醒 [P1｜V1.1]

- **用户故事**：作为内存节俭者，我想把暂时不看的标签一键冻结（释放内存）并在需要时原位唤醒，以便设备不再卡顿且页面不丢。
- **描述**：标签行右键与悬停操作提供"休眠"；休眠调用浏览器原生丢弃机制，标签保持在原位置、原分组，侧边栏中呈灰显休眠态；点击休眠标签即唤醒并激活。**硬约束：仅对可安全丢弃的页面提供休眠**——存在未提交表单、正在播放音视频、正在下载的标签拒绝休眠并说明原因（此为画像三的生死线）。固定文件夹条目与永久固定图标同样支持休眠入口。
- **验收标准**：
  - Given 含未提交表单输入的标签，When 尝试休眠，Then 拒绝并提示"页面有未保存内容"；
  - Given 正在播放音频的标签，When 尝试休眠，Then 拒绝并提示原因；
  - Given 休眠 20 个标签后，When 点击其中一个，Then 该标签唤醒并激活，其余 19 个保持休眠；
  - Given 休眠标签，When 在侧边栏查看，Then 灰显可辨识且保留标题与图标；
  - Given 唤醒休眠标签，When 页面加载完成，Then 其滚动位置或表单状态与浏览器原生行为一致（不额外破坏）。
- **依赖与风险**：浏览器丢弃机制对表单保护的能力边界需实测；唤醒速度依赖浏览器本身。
- **降级形态**：全页与独立弹出窗口支持；弹窗形态提供休眠入口（选中即休眠）。

#### FR-D6.2 休眠白名单 [P1｜V1.1]

- **用户故事**：作为内存节俭者，我想把常用站点与全部固定条目加入"永不休眠"白名单，以便批量操作和自动规则永远不会冻结它们。
- **描述**：白名单两级粒度：①全部永久固定与固定文件夹条目默认视为白名单（开关可关）；②按域名添加白名单。白名单在休眠相关的批量操作与自动规则（FR-D6.3）中一致生效。
- **验收标准**：
  - Given 某域名加入白名单，When 批量休眠 30 个标签，Then 该域名标签全部跳过且提示跳过数量；
  - Given"固定条目视为白名单"开启（默认），When 批量休眠，Then 全部固定标签跳过；
  - Given 关闭该开关，When 批量休眠，Then 固定标签同样被休眠（用户显式选择）。
- **依赖与风险**：无。
- **降级形态**：全形态支持（数据层能力）。

#### FR-D6.3 自动休眠规则 [P2｜V2.0]

- **用户故事**：作为内存节俭者，我想让满足条件的标签（如闲置超过 N 分钟）自动休眠，以便无需手动打理内存。
- **描述**：默认关闭；规则维度：闲置时长 × 作用范围（全部/排除白名单）。每次自动休眠产生一条可撤销的状态提示（撤销 = 全部唤醒）。与 FR-D8.3 规则引擎共用基础设施。
- **验收标准**：
  - Given 规则"闲置 30 分钟自动休眠"开启，When 某标签 30 分钟未激活，Then 自动休眠且状态提示可撤销；
  - Given 白名单域名标签闲置超时，When 规则触发周期到达，Then 跳过该标签；
  - Given 规则关闭（默认），When 任意闲置时长，Then 不发生自动休眠。
- **依赖与风险**：依赖 FR-D8.3 与 FR-D6.2；浏览器后台机制的时间精度限制需在设置中明示。
- **降级形态**：规则配置在全页形态；执行与提示全形态一致。

#### FR-D6.4 与原生内存节省程序的协作声明 [P1｜V1.1] [平台条目]

- **能力陈述**：产品不与浏览器原生内存节省程序（Chrome Memory Saver / Edge 睡眠标签）对抗或重复建设：原生已休眠的标签在侧边栏中呈现与手动休眠一致的灰显态；产品的增量价值在于白名单粒度、按条目手动控制与状态可视化。此定位写入帮助面板与 README。
- **验收标准**：
  - Given 原生内存节省程序冻结某标签，When 侧边栏查看，Then 该标签呈休眠态标识；
  - Given 帮助面板，When 查看，Then 存在与原生功能互补关系的说明；
  - Given README，When 查看，Then 已包含本协作说明。
- **依赖与风险**：无。
- **降级形态**：不适用（说明类条目）。

### 3.7 D7 归档中心

#### FR-D7.1 手动归档 [P1｜V1.2]

- **用户故事**：作为多项目并行的知识工作者，我想把"现在不用但以后会用"的标签或整组收进归档，以便标签栏清爽而条目随手可寻。
- **描述**：归档是介于"关闭"与"收藏"之间的第三种操作：关闭真实标签（进入多层撤销栈）同时将条目（URL、标题、图标、原分组信息）存入本地归档区。入口：标签右键"归档"、网站分组/原生组头部"归档整组"（配合 FR-D7.2 可按域名归档）、批量操作条"批量归档"。归档 ≠ 关闭：关闭只进撤销栈，归档同时留档。
- **验收标准**：
  - Given 归档 1 个标签，When 查看标签栏与侧边栏，Then 标签已关闭且撤销提示出现，归档区新增 1 条；
  - Given 撤销刚才的归档，When 查看，Then 标签恢复且归档区该条目移除；
  - Given 归档含 5 标签的网站分组，When 查看，Then 组内标签全部关闭并生成 5 条归档记录，保留域名归属信息。
- **依赖与风险**：依赖 FR-D8.1（撤销栈覆盖归档动作）；归档保留策略见 OQ-7。
- **降级形态**：全页与独立弹出窗口完整支持；弹窗形态不提供归档入口。

#### FR-D7.2 按域名一键归档 [P1｜V1.2]

- **用户故事**：作为多项目并行的知识工作者，我想对多级域名分组一键归档全部子域标签，以便"这个站点我先放下了"一步完成。
- **描述**：FR-D3.1 多级域名分组的伴生操作：分组头部悬停操作提供"归档整组"；归档记录保留域名层级信息，归档区支持按域名聚合浏览。与基线"分组悬停一键关闭"并存：关闭在前（临时清理），归档紧邻（留档收纳）。
- **验收标准**：
  - Given tencent.com 分组含 cloud/news/文档 3 子域共 7 标签，When 一键归档，Then 7 标签关闭、7 条归档记录按 tencent.com 聚合展示；
  - Given 归档区按域名视图，When 展开某域名，Then 其全部归档条目列出且标注原分组。
- **依赖与风险**：依赖 FR-D3.1、FR-D7.1、FR-D7.3。
- **降级形态**：同 FR-D7.1。

#### FR-D7.3 归档区 [P1｜V1.2]

- **用户故事**：作为现场保护者，我想在一个可搜索的归档区浏览、恢复或彻底删除归档条目，以便"关掉了但永远找得回"。
- **描述**：侧边栏固定空间区提供"归档"入口（角标显示条目数）；归档区支持：按时间/域名两种浏览视图、搜索（复用 FR-D2.1 匹配逻辑）、单条或批量恢复（在当前窗口新建标签）、单条或批量永久删除（二次确认）、清空归档（二次确认）。归档数据仅本地持久；保留策略（永久 vs 上限滚动）见 OQ-7，默认永久保留并提示占用。
- **验收标准**：
  - Given 归档区含 100 条记录，When 搜索关键词，Then 命中列表实时刷新且支持键盘导航；
  - Given 恢复 3 条归档，When 恢复完成，Then 当前窗口新建 3 个标签且 3 条记录离开归档区；
  - Given 批量永久删除，When 确认二次弹窗，Then 记录删除且不可再恢复（明示）；
  - Given 新增归档数据类型，When 发布，Then README 与隐私说明已同步更新。
- **依赖与风险**：本地存储占用的可视化提示；与 D9 导出联动（归档包含在全量导出内）。
- **降级形态**：全页与独立弹出窗口为最佳载体；侧边栏内为折叠面板形态。

#### FR-D7.4 闲置自动归档 [P2｜V2.0]

- **用户故事**：作为多项目并行的知识工作者，我想让闲置超过 N 天的标签自动归档而非堆积，以便标签栏自清洁。
- **描述**：默认关闭；规则维度：闲置天数 × 范围排除（白名单、固定条目）；每次自动归档产生汇总状态提示（可整体撤销）。与 FR-D8.3 规则引擎共用基础设施。产品叙事呼应 Arc"今日标签自动归档"理念，但以显式规则与可撤销性为差异。
- **验收标准**：
  - Given 规则"闲置 7 天自动归档"开启，When 某标签满足条件，Then 自动归档且提示可整体撤销；
  - Given 固定条目，When 规则触发，Then 跳过；
  - Given 规则关闭（默认），When 任意闲置，Then 无自动归档。
- **依赖与风险**：依赖 FR-D8.3、FR-D7.1；"闲置天数"的判定基于标签最后激活时间，浏览器后台机制约束需明示。
- **降级形态**：规则配置在全页；执行全形态一致。

### 3.8 D8 治理与安全网

#### FR-D8.1 多层撤销栈 [P0｜V1.0]（变更：替代基线单层内存撤销）

- **用户故事**：作为现场保护者，我想连续多步操作（关闭、批量、归档）每一步都能反悔，以便放心大胆地整理标签。
- **描述**：将基线"仅最近一次关闭批次、内存态"的撤销升级为多层撤销栈：覆盖关闭、批量关闭、归档、批量移动等改变标签结构的操作；栈深至少 10 步；状态提示的撤销按钮撤回最近一步，长按或右键撤销按钮可回溯任意一步；栈内容持久化到本地（浏览器或面板重启不丢失）。恢复语义继承基线五元组（URL、位置、固定状态、静音状态、分组归属）。
- **验收标准**：
  - Given 依次执行 3 次独立关闭操作，When 依次点击撤销 3 次，Then 3 批标签按逆序全部恢复；
  - Given 关闭 5 个标签后完全重启浏览器，When 打开侧边栏点击撤销，Then 5 个标签恢复；
  - Given 撤销栈已有 10 步，When 执行第 11 步操作，Then 栈保留最近 10 步；
  - Given 恢复某批次，When 其中某标签原分组已不存在，Then 组按名重建（与 FR-D5.1 语义一致）。
- **依赖与风险**：撤销栈的持久化数据量需设上限（超限淘汰最旧并提示）。
- **降级形态**：全形态支持（数据层能力 + 轻量 UI）。

#### FR-D8.2 去重增强：URL 归一化匹配 [P1｜V1.2]（变更：升级基线精确 URL 去重）

- **用户故事**：作为键盘优先的效率玩家，我想让"同一页面的不同链接形态"（带跟踪参数、带锚点）也被识别为重复，以便清理更彻底。
- **描述**：在基线"完整 URL 精确匹配"之上增加归一化匹配层：识别时忽略锚点（# 后部分）与常见跟踪参数（utm_*、spm 等）；清理与复用的**动作对象仍以完整 URL 区分**（保留哪一份遵循基线策略：当前激活 > 已固定 > 最早打开），仅"是否视为重复"的判定采用归一化。n× 角标基于归一化计数。跟踪参数清单内置且随产品更新维护，不做用户可配置（保持克制）。
- **验收标准**：
  - Given 同一页面分别以原始 URL 与带 utm 参数 URL 打开，When 查看，Then 显示 2× 角标且一键清理保留其一；
  - Given 仅锚点不同的两个 URL，When 清理，Then 保留其一（当前激活优先）；
  - Given 查询参数不同但非跟踪参数的两个 URL，When 查看，Then 不视为重复（避免误伤）；
  - Given 基线场景（完全相同 URL 的两个标签），When 清理，Then 行为与基线一致（不回归）。
- **依赖与风险**：参数清单的维护成本；误判风险通过保守清单控制（宁可漏判不可误判）。
- **降级形态**：全形态支持（数据层能力）。

#### FR-D8.3 自动化规则引擎 [P2｜V2.0]

- **用户故事**：作为多项目并行的知识工作者，我想用少量显式规则（闲置归档、按域名自动归组、闲置休眠）让标签栏自运转，以便从重复整理中解放。
- **描述**：统一承载 FR-D6.3、FR-D7.4 及"按域名自动归组"（对未分组标签按域名规则自动加入原生组，可撤销、可在规则中停用）三类规则。原则 8 的落地：所有规则默认关闭、每条可单独停用、每次自动操作进入多层撤销栈并可整体撤销。规则列表提供简洁的"条件 → 动作 → 范围排除"三段式配置，不引入类编程界面。
- **验收标准**：
  - Given 全部规则默认关闭，When 首次安装，Then 无任何自动行为发生；
  - Given 启用"域名 example.com 自动归组"，When 新开该域名未分组标签，Then 自动加入指定原生组且状态提示可撤销；
  - Given 停用某规则，When 对应条件再满足，Then 不再触发；
  - Given 任一自动动作，When 点击撤销，Then 该动作完全回滚。
- **依赖与风险**：依赖 FR-D8.1；自动归组与基线"不碰原生组不可逆状态"原则的边界——仅执行用户显式规则内的新增成员操作，不做关闭/删除原生组。
- **降级形态**：配置在全页形态；执行与提示全形态一致。

#### FR-D9.4 跨设备同步 [P2｜V2.0]

- **描述**：借力浏览器原生同步通道（chrome.storage.sync，数据经用户的浏览器账号同步，**产品仍不经手任何数据**）；同步范围待 OQ-4 决策（候选从窄到宽：仅设置 → +固定集合 → +归档/快照）。超出浏览器同步配额时的降级行为：仅同步较窄分区并明示。隐私说明须明确"同步走你自己的浏览器账号通道，与本产品无关"。

- **依赖与风险**：浏览器同步配额有限（R4）；范围收窄为对策；此功能不改变"数据不离设备"原则的表述（数据仍不经产品服务器）。
- **降级形态**：全形态支持（数据层能力）。

#### FR-D10.4 无障碍保障 [P1｜V1.x 滚动] [平台条目]

- **能力陈述**：全部功能键盘可达；焦点管理与滚动跟进（焦点移动时视图滚动到位）；保留已有的状态播报、菜单角色、减弱动效适配等基线能力并持续扩展。
- **验收标准**：
  - Given 仅用键盘（Tab/方向键/Enter/Esc），When 完成一次"搜索-切换"与一次"批量关闭-撤销"，Then 全程无需鼠标；
  - Given 焦点移出可视区，When 继续导航，Then 视图自动滚动保持焦点可见。
- **依赖与风险**：无。
- **降级形态**：全形态一致。

#### FR-D10.5 隐私承诺与权限最小化 [P0｜全程] [平台条目]

- **能力陈述**："数据不离设备"为宪法级原则的工程化：权限清单冻结为附录 A 所列最小集合，任何新增权限须经需求评审并同步 README 与隐私说明；每版本发布前执行一次隐私回归检查（权限 diff、网络请求 diff、存储数据 diff 三项为零变更或已文档化）。
- **验收标准**：
  - Given 任一版本发布，When 执行隐私回归检查，Then 权限/网络请求/存储数据三项 diff 为零或已有文档说明；
  - Given 附录 A，When 对照产品实际权限，Then 两者一致。
- **依赖与风险**：CWS 对 tabs 等敏感权限审核趋严（R5），以充分的用途说明应对。
- **降级形态**：不适用（全局约束）。

## 5. 非功能需求

### 5.1 性能

- 150 个标签、30 个分组的窗口中，侧边栏刷新无可感知卡顿（标签事件聚合刷新路径不移动用户视口，继承基线行为）；
- 搜索输入到结果呈现 < 100ms（150 标签规模）；
- 面板打开到可交互 < 500ms（冷启动）；
- 自动规则触发不阻塞标签操作主路径。

### 5.2 兼容性

- 目标浏览器矩阵与降级形态见附录 B；原则为"降级而非拒绝"；
- 数据格式带版本号，向前迁移（继承基线原则），跨版本升级不丢用户数据。

### 5.3 隐私与权限

- 宪法级承诺：无后端、无账号、无遥测、零上传；跨设备仅借力浏览器自身同步通道；
- 权限最小集合冻结于附录 A；每版本隐私回归检查（FR-D10.5）。

### 5.4 可靠性

- **用户主动保存的数据（固定集合、快照、归档、规则、设置）不因浏览器崩溃或扩展更新而丢失**——此为产品级承诺，自动保存类能力的边界须在设置中明示（依赖浏览器后台机制，不承诺任意时刻最新）；
- 本地存储写入失败时降级到页面级存储并单向迁移回主存储（继承基线双层策略）。

### 5.5 无障碍与国际化

- 全部功能键盘可达，焦点管理与滚动跟进（FR-D10.4）；
- 保留基线的减弱动效适配、状态播报等能力；
- 中英双语（FR-D10.2），文案全部资源化。

## 6. 数据与迁移策略

**数据范围**（产品级描述，不含格式细节）：固定文件夹与永久固定图标、归档条目、会话快照、自动化规则、撤销栈、偏好设置（主题、聚合阈值、白名单、快捷键覆盖、语言）。

**迁移路径**：

1. **从 OneTab / Session Buddy**：格式导入（FR-D9.3），映射为归档或快照；
2. **导出自由**：全量 JSON（带格式版本）+ 纯 URL 列表双格式（FR-D9.1），确保用户随时可以带着数据离开。

**设计承诺**：所有持久化数据带版本号并配套防御性解析（继承基线原则）——坏数据自动修复或隔离，不让单条坏记录影响整体可用。

### 附录 E：术语表

| 术语 | 定义（全文唯一口径） |
| --- | --- |
| 固定 / 永久固定 | 将页面收进顶部固定图标区的动作/状态；"永久固定"仅在需要与浏览器原生固定区分时使用 |
| 固定文件夹 / 固定空间 | 用户自定义的长期页面集合（文件夹）；"固定空间"是全部固定文件夹所在区域的名称。V2.0 前两者即产品的全部"空间"语义 |
| 空间 | V2.0 概念：多套可切换的固定集合+规则档案（FR-D4.2）。V1.x 文档与界面中不得出现此词指代其他含义 |
| 归档 | 关闭标签同时留档到归档区的第三种操作；区别于"关闭"（仅关闭）与"收藏"（不关闭） |
| 休眠 | 调用浏览器原生丢弃机制冻结标签释放内存；标签保留原位，可唤醒；区别于"关闭" |
| 快照 | 某时刻窗口全部标签的命名存档（FR-D5.1）；区别于"归档"（归档面向条目收藏，快照面向现场还原） |
| 挂起条目 | 固定文件夹中等待用户完成网址输入的临时条目（继承基线机制） |
| 撤销栈 | 覆盖关闭/批量/归档等操作的多步可撤销记录（FR-D8.1） |
| 降级形态 | 不支持侧边栏的浏览器上，产品以弹窗/全页/独立弹出窗口运行的形态 |
