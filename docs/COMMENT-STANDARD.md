# TabHaven 代码注释规范

> 2026-08-27 制定。全仓注释按此规范整改，适用于 `src/` 与 `tests/` 下所有 TS/TSX 文件。

## 一、核心原则

**注释只写「代码无法自我表达的信息」。**

代码能说清楚的，注释一个字都不写。写注释前先问：删掉它会让读者损失什么？
如果答案是"什么也不损失"，那就删掉。

优先级：**让代码自解释 > 改命名 > 加注释**。

## 二、必须写注释的四种情况

### 1. 非直觉的「为什么」（Why）

```ts
// 比较键保留 punycode、仅展示层转 Unicode：两种写法混用会让同一站点被判为
// 不同站点，导致重复标签漏检。
```

### 2. 不明显的约束与前置条件

```ts
/** itemSize 必须等于实际行高：偏大产生空隙，偏小内容溢出重叠。 */
```

### 3. 外部系统的反直觉行为

```ts
// slice(-0) 等价于 slice(0)（返回全量），limit 为 0 时须钳到 1 才能保持淘汰语义。
const cap = Math.max(1, Math.floor(limit));
```

### 4. 安全与数据完整性边界

```ts
// 只输出纯文本分段，由 React 自动转义；拼接 HTML 会引入来自页面标题的注入面。
```

## 三、禁止的九类注释

| 类别 | 反面示例 | 处理 |
|------|---------|------|
| 1. 复述函数名 | `/** 切换静音。 */` 在 `toggleMute()` 上 | 删除 |
| 2. 复述类型名 | `/** 当前键盘选中的搜索结果标签 id。 */` 在 `searchActiveTabId?: number` 上 | 删除；确需说明语义则改字段名 |
| 3. 翻译代码 | `// 如果用户已登录` 在 `if (user.loggedIn)` 上 | 删除 |
| 4. 变更历史 | `// 原先定义在组件体内，现已外提` | 删除；进 git commit message |
| 5. 自我表扬 | `// 这是本项目最扎实的设计` | 删除 |
| 6. 情绪化措辞 | `// 讽刺的是`、`// 值得注意`、`// 坑` | 删除或改写为客观陈述 |
| 7. 行尾琐碎注释 | `// 标签可能已关闭` | 删除；catch 块为空时用语义化说明替代 |
| 8. 内部文档编号 | `（FR-D8.1）`、`（P1⑤）`、`（OQ-4 第一档）` | 删除；需求追踪不写在代码里 |
| 9. 装饰性分隔符 | `// =====`、`// ----` | 删除 |

### 关于「变更历史」的特别说明

`此前 A → 现在 B` 这类叙事属于**设计决策记录**，应进 `docs/` 或 git history，
不进代码注释。代码注释只描述**当前状态**。

例外：当「为什么不用显而易见的写法」本身就是关键约束时，保留**当前状态的原因**，
但删除时间线叙事：

```ts
// ✗ 差：此前用 useMemo 定义，React 不保证缓存稳定，现已提到模块顶层
// ✓ 好：模块级常量，不进依赖数组（useMemo 空依赖不保证引用稳定）
```

## 四、格式约定

### 文件头

仅在该文件**职责无法从路径推断**时写，限 1–3 行，说明职责与边界：

```ts
/**
 * chrome.storage 适配层：单 key 读写 + zod 校验 + 坏数据隔离。
 * 全应用唯一允许触碰 browser.* 的边界，core 层不得引用本文件。
 */
```

不写：作者、日期、修改历史、依赖清单、背景长论。

### 导出 API

导出的函数/类/类型，**有非直觉行为才写 JSDoc**；否则不写。
写了就必须包含增量信息，禁止只有一句复述。

```ts
// ✗ 差
/** 移除标签。 */
export function removeTabs(ids: number[]) {}

// ✓ 好
/**
 * 批量移除标签。返回实际关闭的 id——部分失败（标签已关闭）不抛错，
 * 调用方应依据返回值而非异常判断结果。
 */
export function removeTabs(ids: number[]): Promise<number[]> {}
```

### 内部函数与非导出成员

一律不写 JSDoc。确需说明用单行 `//`。

### 接口字段

仅在字段语义**无法从命名推断**时注释。

```ts
// ✗ 差：与字段名完全重复
/** 是否显示 URL。 */
showUrl?: boolean;

// ✓ 好：说明了非直觉的取值来源
/** 留空则跟随浏览器 UI 语言，解析失败回退 zh-CN。 */
language?: string;
```

### catch 块

空 catch 必须说明**为何可以安全忽略**：

```ts
// ✗ 差
} catch {
  // 标签可能已关闭
}

// ✓ 好：说明忽略理由 + 降级行为已可观测
} catch (error) {
  logDegraded('tabs', '切换静音失败', error);
}
```

## 五、语言与措辞

- 中文，与现有代码一致；术语保留英文原文（`Service Worker`、`memo`、`DNR`）。
- 陈述句，客观语气。禁止口语、反问、感叹、第一人称。
- 注释与代码之间不留空行；独立注释块上方留空行。
- 不使用 emoji。

## 六、长度约束

| 位置 | 上限 |
|------|------|
| 单行注释 | 1 行 |
| 函数/类 JSDoc | 5 行（超出说明该函数可能该拆分） |
| 文件头 | 3 行 |
| 算法说明 | 8 行（超出进 `docs/`） |

## 七、Review 检查项

- [ ] 每条注释是否提供了代码无法表达的信息？
- [ ] 是否存在复述命名、变更历史、自我表扬、情绪化措辞？
- [ ] 是否残留内部文档编号或装饰性分隔符？
- [ ] 文件头/JSDoc 是否超出长度上限？
- [ ] 空 catch 是否说明了可安全忽略的理由？
