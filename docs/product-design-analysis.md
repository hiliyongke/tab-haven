## 📌 TL;DR

- **核心定位**：Tabs 不是"另一个标签管理器"，而是**以「零信任成本」为前提的标签工作台**——用「无账号 / 无服务器 / 零出站网络」换用户的心理安全感，再把省下的信任预算全部投进"误操作可逆"这条主线上。
- **最强的一件事**：**撤销安全网 + 快照 + 选择性恢复 + 影响面预览**构成了一条完整的、竞品普遍缺失的"反悔链"（`src/stores/undoStore.ts`、`src/ui/common/UndoHistoryPanel.tsx`、`src/ui/common/SnapshotsPanel.tsx:63-65,96-105`）。
- **最弱的一件事**：**不可逆动作与可逆动作的处理严重不对称**。快照删除/恢复有二次确认和影响面预览，而"一键清理重复 / 休眠全部 / 快速整理"这三个一次性影响几十个标签的动作**既无确认也无预览**（`src/entrypoints/sidepanel/App.tsx:630-649, 694-723, 772-803`）。
- **本次最该先改的一条（新发现，P0）**：**同步范围的对外口径失真** —— 代码确实把「常驻磁贴（pins）」镜像到浏览器账号通道（`SyncMirror.ts:25-30,133,233`；`context.ts:61` 全量传 `state.pins`），但开关旁的双语说明只写「文件夹与设置」，`PRIVACY.md:70` 还写「**仅**文件夹与设置」。**定性必须准确：这是说明书少写了，不是数据被偷偷上传**——`PRIVACY.md:14/59/67` 三处本已写明含磁贴，且 `MirrorPayloadSchema` 定义内就有 `pins`，属设计意图。修复有界：2 个 locale + 2 处文档。见 **DS-13 / Q0**。
- **结构性风险**：侧边栏首屏被 5–6 层非列表模块占满，主体标签列表被推到折叠线以下（`App.tsx:997-1164`）；设置 schema 46 字段而 UI 只暴露 35 项；卸载扩展即永久清空本地数据且无任何挽留。
- **下一步**：先补「不可逆动作的确认/预览」与「卸载挽留 + 导出引导」两条 P0，再做首屏信息架构减负。

## 1. 项目概述

### 1.1 产品定位

Tabs 是 **Chrome / Edge 的 MV3 侧边栏扩展**，把散乱标签组织成有秩序的空间，并通过撤销、快照与归档降低误操作风险。它的定位可以拆成三层：

| 层     | 内容                                                                   | 证据                             |
| ------ | ---------------------------------------------------------------------- | -------------------------------- |
| 功能层 | 只管理**当前窗口**的标签页，提供侧边栏式组织、搜索、拖拽整理与多层撤销 | `README.md:5`                    |
| 信任层 | 无后端 · 无账号 · 无遥测 · **零出站网络请求**                          | `README.md:7`；`PRIVACY.md:9-16` |
| 商业层 | 永久免费核心；护城河明确排除自有云端账号与自建同步                     | `README.md:158-167`              |

关键的定位取舍：**它放弃了"跨设备"这个标签管理器最常见的卖点**，只保留"经浏览器账号通道的、默认关闭的、可由用户随时撤销的镜像同步"（`PRIVACY.md:64-73`；`src/core/schema/models.ts:220` `syncMirrorEnabled` 默认 `false`）。这是一次清醒的取舍，而不是能力缺失。

### 1.2 形态矩阵（同一套 core，四种壳）

| 形态           | 入口                                                 | 能力范围                                                   | 定位                  |
| -------------- | ---------------------------------------------------- | ---------------------------------------------------------- | --------------------- |
| **sidepanel**  | 侧边栏（主形态）                                     | 全量                                                       | 主工作台              |
| **popup**      | 工具栏图标（Chrome 平台行为：右键图标）              | **仅搜索 + 切换**                                          | 降级形态 / 快速切换器 |
| **options**    | 设置页（`open_in_tab: true`，`wxt.config.ts:26,69`） | 设置 + 导入导出 + 诊断 + 清除数据                          | 配置中心              |
| **about**      | 关于页                                               | 能力总览 + **信任面板**                                    | 信任凭证              |
| **background** | Service Worker                                       | 复用引擎 / 自动快照 / 自动休眠 / 右键菜单 / omnibox / 角标 | 无 UI 的后台能力      |

`wxt.config.ts:66-90` 的 `build:manifestGenerated` 钩子还实现了「兼容变体」：剥离 `sidePanel` 权限与字段、把 action 降级绑定 `popup.html`（`wxt.config.ts:79-89`）。README 标注兼容版管道已建成、随 V2.0 交付（`README.md:78`）。

### 1.3 核心用户链路（5 条主线）

> 说明：以下链路均为「代码可证实的路径」，用户画像与动机属**推断**（本项目无调研数据），已标注。

#### 链路 A：日常找标签（最高频）

`⌘/Ctrl+K` 或 `Ctrl+Shift+F` 聚焦搜索框（`src/entrypoints/sidepanel/hooks/useGlobalHotkeys.ts`、`wxt.config.ts:43-46`）

→ 极端情况：`Esc` 清空并失焦（`useSearchController.ts:222-228`）

**性能基线**：150 标签单次查询中位数 < 100ms；500 标签 < 300ms（`tests/perf/search-perf.test.ts:82-109`）。

#### 链路 C：误关找回（决定留存）

经本产品关闭的标签 → `closeWithUndo` 入撤销栈（`App.tsx:615-620`、`:813-820` 整组关闭走同一批次）

#### 链路 D：收工归档（周期性）

`⌘P` → 「归档当前窗口」→ 关闭并留档（`App.tsx:940-945`）
→ 需要时：快照面板 → 展开行 → **diff 预览**（将新建 / 已存在 / 不恢复三分类，`SnapshotsPanel.tsx:96-105`）→ 勾选部分条目 → 选择性恢复（`SnapshotsPanel.tsx:268-291`）

#### 链路 E：换机迁移 / 备份（低频，一旦失败即致命）

设置页「导出」→ JSON（`format: "tabs.export"`，`EXPORT_FILE_VERSION = 2`，`models.ts:348,360-372`）

## 2. 优势分析

### 2.1 【架构】分层约束不是口号，而是被门禁强制的

`core ← platform ← stores / ui / entrypoints` 的单向依赖不是文档约定，而是有测试守卫：

- `core/**` 零 `chrome.*` / DOM / React（`CODEBUDDY.md` 分层架构红线）；
- `platform/**` 是唯一触碰 `chrome.*` 的层；UI 不得绕过（`CODEBUDDY.md`）；
- **持久化数据类型与 `core/schema` 的 zod schema 同源**（`z.infer`，`CODEBUDDY.md` 代码风格规则），不存在"另立一份类型定义"。

**收益是可验证的**：core 层是唯一要求接近满覆盖的层，实测 100%（`vitest.config.ts` 阈值注释）。搜索、去重、keeper 策略、撤销、洞察等纯领域逻辑全部可在 node 环境下单测——这也是 `tests/perf/search-perf.test.ts` 能存在的根本原因。

### 2.2 【工程】把"踩过的坑"写成注释，形成可传承的防御性设计

这个项目最突出的工程品质是：**几乎每个非直觉的写法旁边都写了"为什么"**。抽查到的实例：

| 位置                           | 防御的问题                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------- |
| `App.tsx:272-284`              | `handleLocateActive` 必须 memo，否则每次渲染都会解绑/重绑键盘与消息监听，还会让挂起队列重复执行 |
| `App.tsx:294-298`              | 渲染期写 ref 会在并发渲染下把未提交值泄漏给事件监听                                             |
| `App.tsx:367-368`              | 数据初始化 effect 的依赖**刻意不含 `t`**：否则切一次语言等于重启一次面板                        |
| `Dialog.tsx:24-30`             | 弹窗栈：嵌套弹窗时同级 `stopPropagation` 拦不住，只有栈顶有权响应 Esc/Tab                       |
| `Dialog.tsx:61-68`             | 初始聚焦推迟到微任务，否则 `focus()` 打在 `display:none` 子树上静默失效                         |
| `CommandPalette.tsx:79-82`     | 用**递增 tick 而非布尔**标记拼音就绪：`set(true)` 会被 React 丢弃（值未变），拼音命中永远不出现 |
| `useSearchController.ts:29-34` | 空 Set 必须是**模块级常量**，否则击穿下游 memo 链                                               |
| `VirtualRowList.tsx:88-95`     | 显式钳制 `start`，不依赖浏览器"内容收缩→scrollTop 钳位"的 UA 行为                               |
| `VirtualRowList.tsx:108-121`   | rAF 节流必须记录最新值再提交，否则停止滚动时最后一帧丢失                                        |
| `tabInsights.ts:58-64`         | 洞察用**宽松页面身份键**（www 归一化），去重/复用用严格口径——两套刻意不同，各司其职             |
| `models.ts:15-24`              | 集合上限只加在"外部输入"侧，自由文本刻意不加逐字符串上限（避免存量真实数据被判坏数据清空）      |

这类注释不是炫技，而是把"曾经线上炸过/测出来过"的具体故障固化成了约束。**这是本项目最值得保留的资产。**

### 2.3 【体验】可逆性设计是完整闭环，不是单点功能

「误操作可逆」在 Tabs 里是一条**贯穿四个层次**的链：

1. **即时撤销**：`⌘Z` / StatusToast 上的撤销按钮（`src/ui/common/StatusToast.tsx:28-32`）；
2. **回溯撤销**：撤销历史面板可点任意历史批次（`UndoHistoryPanel.tsx:121-154`），并标注来源 `kind`（archive / close），让用户知道"这批是我关的还是归档带走的"（`UndoHistoryPanel.tsx:28-40`）；
3. **栈外补救**：`chrome.sessions` 最近关闭（`UndoHistoryPanel.tsx:156-190`）；
4. **长期留档**：快照 / 归档 + 恢复前 diff 预览 + 选择性恢复 + 影响面确认（`SnapshotsPanel.tsx:63-65, 96-105, 244-291`）。

**关键细节**：整组关闭走**一次**撤销批次而非 N 次（`App.tsx:808-812` 注释）；撤销批次记录 `windowId`，避免切窗后恢复到错误窗口（`models.ts:262-266`）；清理重复后对"保留项"播放脉冲高亮，让"留下了谁"可见（`App.tsx:642-643`）。

### 2.4 【反馈】"不静默"是写进代码纪律的

全项目对"空跑"的处置高度一致——**按钮恒可用时，无候选必须给反馈**：

| 场景                     | 处理                                    | 位置                     |
| ------------------------ | --------------------------------------- | ------------------------ |
| 清理重复无候选           | `notify(t('duplicates.cleanNone'))`     | `App.tsx:637-640`        |
| 休眠全部无候选           | `notify(t('discard.allInactiveNone'))`  | `App.tsx:704-707`        |
| 唤醒全部无候选           | `notify(t('discard.wakeNone'))`         | `App.tsx:732-735`        |
| 快速整理无需变更         | `notify(t('footer.quickRegroupNone'))`  | `App.tsx:780-783`        |
| 文件夹条目都已打开       | `notify(t('fixed.allOpen'))`            | `App.tsx:880-883`        |
| 组内无可收藏标签不建空夹 | 返回 false + 区分文案 `fixed.saveEmpty` | `App.tsx:749-752`        |
| 设置写盘失败             | 页面明确提示（否则"开关点不动"）        | `SettingsPage.tsx:78-85` |
| 稍后读落盘失败           | 如实报错，不谎报"已加入"                | `App.tsx:934-938`        |

配套还有**并发互斥**：`batchBusyRef`（`App.tsx:134-147`）、`saveInFlight`（`SnapshotsPanel.tsx:164-180`）、`restoringId` / `deletingId`（`SnapshotsPanel.tsx:251, 297`）、`switchingRef`（`useSpaces.ts:41-43`）。这些防的是"连点产生两份数据"。

### 2.5 【可达性】不是补丁，是基线

核验到的可达性事实（非泛泛而谈）：

- **统一弹窗行为契约**：`useModalA11y` 提供 打开聚焦首项 / Tab 焦点陷阱 / Esc 关闭 / 关闭后焦点恢复 / 背景滚动锁定（含滚动条宽度补偿）（`Dialog.tsx:48-139`），被 `DialogShell` / `CommandPalette` / `OnboardingTour` 共用；
- **命令面板是完整 ARIA combobox**：`role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant` 四件套齐全（`CommandPalette.tsx:443-459`），并刻意用 `div + role=listbox/option` 而非原生 `<select>`，因为可自定义 option 需 Chrome 135+ 而本产品最低支持 114（`CommandPalette.tsx:461-467`）；
- **读屏播报覆盖**：搜索命中数 `<output aria-live>`（`App.tsx:1017-1019`）、popup 播报**实际渲染行数**而非命中数（`popup/App.tsx:207-212`）、设置页操作结果 `role="status"`（`SettingsPage.tsx:387-392`）、失败走 `role="alert"`（`StatusToast.tsx:19-25`）；
- **选中索引钳制**：结果集收缩时钳制，避免 `aria-activedescendant` 指向空项（`popup/App.tsx:160-164`、`CommandPalette.tsx:384-386`）；
- **WCAG 2.5.8 命中区**：引导进度点视觉 6px 高但用 `.tour-dot` 撑到 ≥24px 命中（`OnboardingTour.tsx:111-127`）；
- **对比度有自动化门禁**：`tests/ui/design-tokens.test.ts:196` 「对比度矩阵（2 主题 × 6 色相，WCAG 2.1 AA）」，另有字号/间距/圆角/阴影刻度与「交互基线」守卫（同文件 `:233, :297, :332, :363`）；
- **主题三态**：`system / light / dark`（`models.ts:89`），`theme-init.ts` 头部同步避免闪烁（`README.md:117`）；
- **动效尊重系统偏好**：`prefers-reduced-motion` 在 `TabRow.tsx:138` 与 `VirtualRowList.tsx:168` 都做了降级。

### 2.6 【一致性】同一语义在三个入口复用同一内核

- 搜索：`SearchEngine` 被 sidepanel（`useSearchController.ts:121-133`）、popup（`popup/App.tsx:65-77`）、命令面板（`CommandPalette.tsx:151-177`）共用，且三处都用同一套 pinyin tick 机制；
- 拼音就绪信号：popup / 命令面板 / 侧边栏三处同口径（`popup/App.tsx:83-100`、`CommandPalette.tsx:179-193`、`useSearchController.ts:168-185`）；
- keeper 策略：`planDuplicateCleanup` 是模块级纯函数，**徽章计数与清理动作共用同一份计算**，杜绝"徽章显示 3 个、点下去说没有"（`App.tsx:66-91`）；
- 弹窗：全部走 `DialogShell` / `useModalA11y`，无原生 `confirm/prompt`（`Dialog.tsx:7-10` 契约声明）。

### 2.7 【隐私】把"零网络"从文档承诺变成可验证功能

- **权限冻结 + 双向校验**：`scripts/privacy-check.mjs` 校验 manifest 权限与 `PRIVACY.md` 第 2 节**逐项双向一致**（新增未记录 / 记录已删除都失败，`:113-114`）；
- **扫描构建产物而非只扫源码**：`:18` 指向 `.output/chrome-mv3`，注释明确"只看源码会让第三方依赖打进 bundle 后的网络调用不可见，而用户安装的是产物"（`PRIVACY.md:91`）；
- **信任面板**：关于页把 12 项权限逐条映射到用途，并给出**用户可自行验证的 DevTools 教程**（`AboutPage.tsx:200-225`）——不要求用户信任声明，而是教会用户验证；
- **诊断导出刻意不含页面标题与网址**（`SettingsPage.tsx:154-159`），使"导出诊断"这一用户主动行为不泄露浏览内容；
- **实际核查**：`grep -rnE "\bfetch\(|XMLHttpRequest|WebSocket|sendBeacon" src/` → 无命中；`dangerouslySetInnerHTML` → 无命中；`eval|new Function` → 无命中。

### 2.8 【国际化】零漂移，有守卫

实测（命令输出）：`zh-CN` 744 键 / `en` 744 键，**差集为空**（`src/i18n/locales/*/translation.json`），由 `scripts/i18n-dead-keys.mjs` 守卫。注意 `AboutPage.tsx:17-20` 特意说明 i18n 键一律写字面量，因为死键守卫靠"源码中出现精确键串"判定，模板拼接会让整批键被误判为死键——这是把工具约束反哺到编码规范的典型案例。

### 2.9 【性能】有明确的量化基线与防 flaky 方法

`tests/perf/search-perf.test.ts` 的方法论本身值得肯定：预热（排除 JIT 一次性成本）、取**中位数**而非最大值（抗毛刺）、**阈值按规模分档**（500 标签用 300ms 而非 100ms）、附加"查询确实命中"的正向断言（`:88-89`，防"快是因为啥都没做"）。

UI 侧同样有针对性优化：`TabRow` 关闭 dnd-kit 让位过渡以稳定碰撞矩形（`:96-101`）、`sortable.listeners` 必须 memo 否则击穿 `RowItem` 的 memo（`:116-129`）、虚拟列表行高**实测校准**而非依赖估算公式（`VirtualRowList.tsx:74-101`）。

### 2.10 【引导】三层引导可收起、可回看、可撤销

- 首启引导延迟 900ms 弹出，让用户先看到真实列表一眼；**延迟窗口内用户一旦操作即放弃本次自动弹出**（`App.tsx:423-445`）——避免"教的东西盖住被教的对象"；
- Esc 只关本次（`onDismiss` 不落盘），下次打开仍可再看（`OnboardingTour.tsx:14-15, 32`）；
- 设置页提供「重播引导」入口（`settingPresets.tsx:174-179`）；
- 预设画像带**撤销出口**：套用前快照旧值，可一键还原（`settingPresets.tsx:61-97`）——降低探索惩罚。

### 3.7.1 建议：降级可见性做三级分层，而不是"全量暴露"

120 处全量弹 toast 会瞬间淹没用户（其中大量是后台周期任务的瞬时抖动）。建议按**用户是否需要改变行为**分级：

| 级别                      | 判据                        | 呈现                                                      | 覆盖的 scope                                                                       |
| ------------------------- | --------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **G1 阻断性**（必须行动） | 用户不处理就会持续错/持续丢 | **持久标记**：设置页对应设置行 + 面板顶部常驻条，直到恢复 | `sync-mirror` / `storage` / `cross-page-lock`                                      |
| **G2 可感知降级**         | 功能存在但部分失效          | 一次性 toast + 去重                                       | `auto-snapshot` / `auto-discard` / `auto-group` / `reuse-coordinator` / `no-cache` |
| **G3 内部噪音**           | 用户无感或瞬时自愈          | 只进诊断缓冲，不打扰                                      | `window-cache` / `sessions` / `search` / `tab-sync`                                |

三条硬约束（否则这套机制自己会变成噪音源）：

1. **同一 scope 去重**（`Set` + 冷却窗口），避免每 30s 一次的定时快照失败刷屏；
2. **恢复后必须清除**（成功写入复位标志位），否则"修好了还在报错"；
3. **文案可行动**：G1 不说"同步失败"，说"跨设备同步已停止（超出浏览器同步配额）——**导出一份备份**"，并直接给导出按钮。

> 注：团队曾提出"当前无活跃调用点"的几条（EmptyState / `orderLockedBySortMode` / SectionList 兜底空态），经我复核**判定有误**——`EmptyState` 有 4 处活跃调用（`popup/App.tsx:215`、`ListStates.tsx:36,57,78`）；`orderLockedBySortMode` 在 `sortMode='recency' + tabOrderSync=true` 时可达（`useTabDragHandlers.ts:108-116`）。**这几条保留在缺陷清单内，不因"不可达"而移除。**

### 5.3 Tabs 的差异化护城河（按可信度排序）

1. **零账号 + 零云 + 零网络 + 可自证** —— 竞品普遍依赖账号与云同步，Tabs 直接放弃该卖点，并把隐私做成"权限面板 + 门禁脚本 + 用户可自验"三件套（`AboutPage.tsx:200-225`、`scripts/privacy-check.mjs`）。**成本在工程纪律，不在功能开发，短期难复制。**
2. **撤销栈 + 批次回溯 + 浏览器最近关闭兜底** —— 三者在**同一屏**内可用（`UndoHistoryPanel.tsx:121-190`），且区分来源标签（archive / close，`:36-40`）。矩阵中 6 个竞品**全部为 ❌**。
3. **恢复前 diff 预览 + 勾选剔除** —— 把"恢复"从"盲开一堆标签"变成"可预演、可裁剪"，`snapshots.empty` / `restoreSelectedEmpty` 等空态文案齐全。**独家。**
4. **迁移器（OneTab 文本 + Workona JSON）** —— 把竞品的存量用户变成自己的新用户，`parseWorkona` 有 1MB 上限、仅 http(s)、resources 收藏并入等边界处理（`workonaImport.ts`）。

### 5.4 能力差距与威胁

| #   | 差距                               | 说明                                                                                                                    | 在本报告的对应项                      |
| --- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| G1  | **缺可见的反馈与协作渠道**         | 零账号产品失去"账号即触达"；竞品有官网/社群/支持邮箱，Tabs 产品内无任何出口                                             | DS-5、DS-9（120 处降级 0 个 UI 出口） |
| G2  | **跨平台能力弱于 Toby / Sidekick** | 二者有独立客户端或完整云端工作区；Tabs 受限于 MV3 与"只管当前窗口"，无法覆盖"跨窗口/多设备工作区"                       | FC-1、IX-9                            |
| G3  | **学习曲线偏长**                   | 侧栏首屏信息密度高、底栏 11 个图标；竞品（尤其 OneTab）主打"零学习成本"                                                 | IA-1、IA-2                            |
| G4  | **无移动端 / 无跨浏览器**          | 依赖 Chrome MV3 API（`sidePanel` / `tabGroups` / `declarativeNetRequest`），Firefox/Safari 迁移成本高；Toby 等有 Web 端 | 架构性取舍，非缺陷                    |

### 5.5 竞品维度未核实事项

1. Chrome Web Store 各竞品的**安装量与评分**：未取到可靠来源，不引用。
2. Arc 停更后的用户流向与替代方案接受度：无可靠公开数据。
3. Workona 是否发布过 sunset 公告：官方公告未找到，按"活跃"处理。

### 5.6 与本报告结论直接相关的三点

1. **「零账号 + 零网络 + 可自证」是当前唯一的硬差异化**，但**它同时也是增长天花板**：第 5.3 条的护城河与第 5.4 条的 G1/G2 是同一枚硬币的两面。
2. **迁移器是"已建成但没接线"的增长资产**：`SnapshotsPanel.tsx:633-640` 的入口是快照面板底部的一个文字按钮，首启引导三步（`OnboardingTour.tsx:63-83`）**完全没提"你可以从 OneTab / Workona 搬过来"**。
   ⚠️ **附带风险**：OneTab **闭源、无官方 SDK 或格式变更日志**，Tabs 的导入依赖逆向的文本格式，契约可能随对方版本变更而失效——需要有失败时的明确提示（当前有 `snapshots.importUnparsed`，但未告知用户"可能是对方改了格式"）。
3. **"只管当前窗口"是与竞品的正面分野，但产品内没有解释**：`showOtherWindows` 默认开启但只读（`models.ts:227`），用户看不到别的窗口的标签时，会理解为**功能坏了**而不是设计选择。

### 6.2 假设

- 假设 1：**目标用户是标签过载的知识工作者**（推断，无调研数据支撑）。依据：`aggregationThreshold` 默认 2、`groupMode` 三档、`pinyinSearch` 默认开启、`searchHistory` 默认开启、`README.md:72` 习惯洞察的三类输出都指向"长期开着一堆标签"的人群。
- 假设 2：**用户安装的首要动机是"别再丢标签"**（推断）。依据：`autoSaveSnapshots` 默认**开启**（`models.ts:145` 注释明确"关窗后标签全丢是最大痛点，出厂不保护等于放弃安全网"），且撤销/快照/归档的能力密度显著高于组织类能力。
- 假设 3：**已实测修正** —— Chrome 侧边栏面板宽度 **320–640px（出厂默认 400px）**，用户可拖拽调整且**不会被记忆**（每次打开可能回到默认或上次值，取决于 Chrome 版本）。因此 IA-2（底栏换行）在 **320px 最窄态成立**，在 400px 默认态需实际渲染验证；结论保守表述为「窄面板必然换行」而非「所有用户都换行」。
