# Chrome API 新能力落地评估（Tabs）

> 评估日期：2026-10-11 · 依据：`chrome-extensions` 技能 + 本仓库隐私/权限/分层红线。
> 排序原则：**零新权限优先**；涉及新增权限或新能力形态的一律先报拍板，不自行实现。
> 工作量为单人日估算（含测试与双语文案）。

## 结论先行

- **可立刻做（零新权限，共约 2.3 人日）**：标签组批量折叠、omnibox 语法扩展、最近关闭窗口恢复、通知加「撤销」按钮、右键菜单补齐反馈。
- **需你拍板（1 项）**：Prompt API（端侧模型）—— 无新权限、不联网，但会抬高 `minimum_chrome_version` 且强依赖用户端模型可用性，3–5 人日。
- **建议不做（7 项）**：`history`、`identity`、content script 注入、offscreen、远端 LLM、`tabCapture`/`desktopCapture`、`userScripts` —— 前两项与产品宪法直接冲突。
- 任何新增权限都必须同时改 `wxt.config.ts` + `PRIVACY.md`，否则 `pnpm check:privacy` 直接失败。

## B. 需拍板后才能动

### B-1 Prompt API（`LanguageModel`，端侧 Gemini Nano）— **待你决定**

- **权限影响**：**无新权限**，模型在浏览器本地推理、不产生 Tabs 侧网络请求，**不违反零出站红线**。
- **可落地的场景**：① 分组自动命名（比按域名聚合更贴合语义）；② 自然语言搜索（"上周看的那个部署文档"）；③ 快照周报的摘要。
- **工作量**：3–5 人日（含可用性探测、降级路径、双语文案、测试）。
- **风险与成本**：
  1. 需 Chrome 138+ 且用户已下载端侧模型 —— 必须做 `LanguageModel.availability()` 探测，**不可用则静默回退到现有规则**，不能弹错误吓用户；
  2. 会抬高 `minimum_chrome_version`（当前 `wxt.config.ts:15` 为 114），直接影响旧内核用户群；
  3. 侧边栏/SW 均可调用，但长会话在 SW 内会被回收 —— 建议只在侧边栏 DOM 上下文跑；
  4. 需在 `PRIVACY.md` 第 1/2 节补一条口径说明（不申请权限，但属于「能力变更」，宪法要求对外口径同步）。
- **建议**：先做 C-1～C-5；Prompt API 单独排一次，用「分组自动命名」做单点验证，验证通过再扩其余场景。

### B-2 `chrome.downloads`（导出备份免选路径）

- **权限影响**：**新增 `downloads` 权限** → 须改 `wxt.config.ts` + `PRIVACY.md` 第 2 节 + 通过 `check:privacy`。
- **收益**：导出少一次「另存为」对话框。
- **建议**：**不做**。为一次点击省事新增一项安装期权限，与「权限冻结、最小集合」的产品承诺相抵。

## C. 建议不做

| 能力                                   | 为什么不做                                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `chrome.history`                       | 把时间线搜索扩到真实浏览历史需新增 `history` 权限，与 `PRIVACY.md`「不读浏览历史」的对外口径**直接冲突**，隐私面显著扩大 |
| `chrome.identity` / 自有账号           | 违反产品宪法（无自有账号、无自有服务器），属明确排除项                                                                   |
| content script + `chrome.scripting`    | 「零注入」是当前的信任卖点；一旦注入就要 host 权限或 activeTab，且引入页面兼容负担，收益不对等                           |
| offscreen document                     | 无录屏/剪贴板/大 DOM 解析场景；且 offscreen 内绝大多数 `chrome.*` 不可用，本项目的活都在 SW 侧                           |
| 远端 LLM / 任何 `fetch`                | 违反零出站网络红线（`check:privacy` 会直接拦）                                                                           |
| `chrome.tabCapture` / `desktopCapture` | 与标签组织无关，且需录制类权限与状态机，纯负担                                                                           |
| `chrome.userScripts`                   | 面向脚本管理器形态，与本产品无关，且需用户手动开启「允许 User Scripts」                                                  |

## 落地流程（任何一项开工前）

1. 判定是否新增持久化数据 → 是则先改 `core/schema` 并同步 `PRIVACY.md` 第 3 节与 3.1 键清单；
2. 判定是否新增权限 → 是则同时改 `wxt.config.ts` 与 `PRIVACY.md` 第 2 节，跑 `pnpm check:privacy`；
3. `chrome.*` 只能落在 `src/platform/**`（`background` 子模块属 entrypoints，只做编排）；
4. 新增 UI 文案补 `zh-CN` 与 `en` 两份，跑 `pnpm check:i18n`；
5. 收尾跑 `pnpm check`，更新 `CHROMEWEBSTORE.md` 的功能描述与 Version History。
