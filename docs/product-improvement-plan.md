## 0. 执行原则（先立规矩，再动代码）

| 原则              | 具体要求                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **最小改动**      | 只修根因，不顺手改变既有设计约定（阈值 / 窗口 / 状态集 / 接口形状）。计划外发现的同类问题记入 §8 观察项，不在本轮改                              |

### FIX-01 · 批量动作影响面可见化（P0，**不阻断**）

> **决策 D2（2026-09-30 拍板）**：采用「影响面提示」而非「强制确认弹窗」。三处动作保持一键执行，把影响面做进**入口提示**与**执行回执**，不新增阻断步骤，不给高频用户加摩擦。

**现状证据**

- 「一键清理重复」`src/entrypoints/sidepanel/App.tsx:630-649`：直接 `planDuplicateCleanup` 后 `closeWithUndo`，无确认无预览。
- 「休眠全部」`App.tsx:694-723`：直接 `Promise.all(discardTab)`。
- 「快速整理」`App.tsx:772-803`：直接 `regroupTempArea`。
- 反例（已有正确做法）：`src/ui/common/RestoreConfirmDialog.tsx:8-19` —— 恢复会一次性新建整批标签且**不在撤销栈覆盖范围内**，因此强制「将打开 N 个标签（含 M 个分组）」确认。
- **注意**：三处属于「关闭」路径，**已有**撤销栈兜底（`closeWithUndo` / 自动休眠台账 / `RestoreConfirmDialog.tsx:8-12` 注释口径），严重度低于恢复；诉求是**影响面可见**，不是拦截。

**目标行为（不阻断）**

1. **入口层**：底栏图标的 `title` 与徽章预判影响面 —— 清理重复已有徽章 `duplicateCount`（`FooterToolbar.tsx:123-131`）；休眠全部与快速整理补上「将影响 N 个」的 `title`（当前为静态文案 `discard.allInactive` / `footer.quickRegroupHint`）。
2. **回执层**：执行后用既有 `StatusToast`（`src/ui/common/StatusToast.tsx:7`）给出结构化结果 —— 关闭 N 个、休眠 N 个、重组 N 个组；影响面 ≥5 时附带保留域名 Top3。
3. **可反悔层**：关闭类（清理重复）走既有撤销管线；休眠类走既有「全部唤醒」；**快速整理不可逆**，回执中必须显式说明（它打散并重建浏览器原生组，不进撤销栈 —— 见 `RestoreConfirmDialog.tsx:8-12` 对撤销覆盖范围的口径）。
4. 无候选时保持既有显式反馈（`duplicates.cleanNone` / `discard.allInactiveNone` / `footer.quickRegroupNone`）。

**改动清单**

| 文件                                           | 改动                                                                                                                |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `src/entrypoints/sidepanel/App.tsx`            | 三处 handler 在**执行前**算好影响面，`notify()` 输出结构化回执（复用既有 `notify` / `notifyError`，不新增提示通道） |
