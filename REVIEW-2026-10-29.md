## 一、P1：已修复

### P1-1 锁内重读会自锁，坏数据场景下整条链路悬挂

- 位置：`apps/extension/src/platform/storage/DataRepository.ts:75`（`recoverElements`）
- 证据：store 的标准写法是「持锁 → 锁内重读」（如 `stores/data/initSlice.ts:111-118`、`undoStore.ts:136`）。
  `read()` 命中坏数据时会走 `recoverElements`，**再申请同一把锁**；Web Locks 不可重入，
  同名请求永久排队——不抛错、不留日志，表现为启动卡住。
- 为什么此前没暴露：vitest 环境无 `navigator.locks`，`withCrossPageLock` 直接降级执行，
  这条路径在测试里永远畅通。
- 修法：新增 `withCrossPageLockIfAvailable`（`ifAvailable: true`），取不到锁时不等待，
  只做「恢复 + 隔离」不回写，把合法值交回调用方。
- 回归：`tests/platform/storage/data-repository-lock-reentry.test.ts`（用不可重入锁模拟，
  旧实现会超时）。

### P1-2 命令面板里的快照恢复确认弹窗点不动

- 位置：`ui/panels/CommandPalette.tsx:261`
- 证据：面板是原生 `<dialog>` + `showModal()`；`DialogShell` 默认 `createPortal(..., document.body)`。
  模态 dialog 会让其子树之外的一切 inert，portal 出去的确认弹窗照样 inert —— 用户看得见、点不了。
- 修法：`DialogShell` / `ConfirmDialog` / `RestoreConfirmDialog` 增加 `inline` 选项，
  面板内改为就地渲染（成为 dialog 后代）。
- 回归：`tests/ui/dialog-shell.test.tsx` 新增「默认 portal / inline 留在调用处」两条。

### P1-3 书签导入的文件夹名走了 i18n，违反落盘名不变量

- 位置：`stores/data/transferSlice.ts:268`
- 证据：`const name = translate('书签导入')`。而 `core/snapshot/defaultNames.ts` 文件头明确写着：
  默认名是落盘值、会进备份，**按界面语言生成会让同一份数据出现两种名字，破坏「同名合并」**。
- 修法：加入 `DEFAULT_FOLDER_NAMES.bookmarkImport`，导入侧改用常量（`@i18n-ignore` 块内）。
- 回归：`pnpm check:i18n` 词条数不变（802），无新增待译键。

### P1-4 原生分组移动把「标签序号」当成「组序号」

- 位置：`ui/hooks/useTabDragHandlers.ts:260` → `platform/tabs.ts:481`
- 证据：`computeGroupMoveIndex` 返回的是**标签索引**（其注释与实现都是标签口径），
  而 `chrome.tabGroups.move(id, { index })` 的 index 是**组序号**。窗口里存在未分组标签时两者不等，
  表现为「拖到某组后面，组却落到别处」。
- 修法：新增 `computeNativeGroupMoveIndex`（按组的首个标签位置还原组顺序，先摘自身再定位），
  原生组分支改用它；虚拟分区仍走标签索引。
- 顺带：`SectionActions.onGroupMove` 是**从未被读取的死属性**（只有类型声明与 App 赋值），
  连同 App 里的 handler 与 selector 一并删除。

### P1-5 定时自动快照的闹钟被 SW 唤醒反复重置

- 位置：`entrypoints/background.ts:554` → `platform/background/autoSnapshot.ts:109`
- 证据：SW 每次启动都会 `syncAlarms`，而「是否重建」只靠闭包内变量 `snapshotAlarmSignature`，
  重启即归零；`alarms.create` 同名会**重置触发时间**。SW 被唤醒得越频繁（自动休眠开启时每分钟
  一次闹钟，外加标签事件），快照周期就被推得越远，极端情况下永不触发。
- 修法：以浏览器侧现有闹钟为准（`browser.alarms.get` 比对 `periodInMinutes`），同周期直接返回；
  自动休眠闹钟同口径。
- 回归：`tests/background/auto-snapshot.test.ts` 新增「SW 重启（签名归零）不重建同周期闹钟」。

### 6.5 判定与未修

- **文档 P0 的处置**：`tabs` 权限的真实读取范围比文档更宽（角标与地址栏建议读所有普通窗口，仅内存计算、不落盘、不联网）。本轮选择**改文档对齐实现**，因为它不改变任何用户可见行为；若产品要的是收紧代码，把 `badge.ts:52` 与 `omnibox.ts:35` 的查询改成受 `showOtherWindows` / `searchAllWindows` 控制即可，属一行级改动。
- **本轮发现的三项小债已在 6.9 收口**：`coalescedWriter` 无时序测试、`oneTabImport` 超限静默、`tabs.Tab.language` 的 `und` 哨兵。本地 Node 22 与 `engines >=26` 的差异由 CI 侧 `engine-strict` 挡住发布，本地仍只会看到警告。
- **不能修**：`engine-strict=true` 会让当前 Node 22 环境所有命令直接失败（项目要求 Node ≥ 26），属环境治理，不该由门禁脚本单方面决定。
