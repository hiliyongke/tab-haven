# Tabs V1.0 发布前跨领域评审报告

**评审日期**：2026-09-04
**评审对象**：Tabs（WXT + React 19 + TypeScript 浏览器扩展），`src/` 105 个源文件
**评审目标**：第一版对外公开发布 —— 代码整洁无误、文档齐全、质量达业界权威标准
**评审方式**：五个方向并行独立评审（代码质量 / 架构设计 / 文档规范 / 安全性 / 测试），辅以门禁实测

---

## 0. 评审结论（TL;DR）

| 方向     | 结论                                                         | 阻断发布的问题 |
| -------- | ------------------------------------------------------------ | -------------- |
| 代码质量 | 良好，有 5 项 P1 缺陷                                        | 否             |
| 架构设计 | 分层清晰，1 处 P0 数据丢失 + 1 处分层破坏                    | **是（已修）** |
| 文档规范 | 发布必备文档大面积缺失，**4 处描述与代码事实不符**           | **是（已修）** |
| 安全性   | 基盘扎实（零 XSS / 零 ReDoS / 无原型污染），1 条可利用提权链 | **是（已修）** |
| 测试     | 覆盖不均衡，**无任何 CI**，门禁跑不全                        | **是（已修）** |

**评审前门禁实测**：`tsc` 通过、`eslint` 通过、`vitest` **4 个测试文件失败**（313/317 通过）、`check:privacy` 遗漏主机权限、**无 CI 配置**。
**整改后**：`pnpm check` 全链路通过（format → typecheck → lint → i18n → 375 tests + 覆盖率阈值 → build → privacy），退出码 0。

> 关键判断：本项目**不是**「需要重写」的项目。分层、错误处理、坏数据隔离、事务化导入等设计均在水位线之上。
> 真正阻断发布的是三类问题：**测试红灯**、**文档说谎**、**一条可利用的提权链**——均已修完（见第 2 节）。

## 5. 保留项与后续计划

以下 5 项为**大体积重构或依赖人工交互的测试**，不修不影响正确性、安全性与发布。
列出待办理由与建议路径，避免后续接手时重复评审。

### CQ-5 · 巨型文件拆分（P1，改动量最大）

- `src/entrypoints/options/SettingsPage.tsx`（≈1400 行）：`buildSections` 内联约 370 行纯配置，
  且编辑器组件（`WhitelistEditor` / `NoCachePatternEditor` / `NoCacheToggle`）与 `Section` / `Row`
  同文件，拆出配置层会与渲染层互相引用成环 —— 需先把编辑器组件沉到 `settingControls.tsx`，
  再拆 `buildSections` 到 `settingSections.tsx`，形成单向依赖 `SettingsPage → settingSections → settingControls`。
- `src/stores/dataStore.ts`（≈900 行）：20+ action 混合 folders / pins / settings / transfer 四类职责，
  建议 zustand slice 化。**注意**：拆 slice 会改变 `useDataStore.getState()` 的选择器面，
  现有 40+ 个测试与 5 个调用方需同步调整。
- 建议节奏：一次只拆一个文件，拆完跑全量门禁再进行下一个。

### AR-3 / TS-2 · 主控制器拆分与测试（P2 / P0）

- `sidepanel/App.tsx`（38KB）单组件 30+ store 订阅、8 个 `useEffect`。
  先拆 hook（`useLocateActive` / `usePendingActions` / `useAutoGrouping`）再写测试，
  否则测试无法定位可断言单元。
- `useTabDragHandlers.ts`（11KB 拖拽状态机）是测试收益最高的入口：
  纯状态机、无 DOM 依赖，可先于组件测试。

### TS-6 · 设置页交互测试（P1）

- 当前 5 个用例全是渲染冒烟。导入 / 导出 / 重置 / 白名单编辑均无覆盖。
- 难点：文件导入需 mock `FileReader` 与 `URL.createObjectURL`，
  建议先为 `MAX_IMPORT_BYTES` 守卫补纯逻辑测试（不依赖 DOM）。

### SE-3 / SE-4 · IDN 展示防护与白名单 punycode（P2）

- 两者共用同一块基建（`core/fixed/PinIdentity.ts` 的归一化），建议一并处理。
- 注意：SE-3 是**展示层**问题（归组键已保留 punycode，无安全风险），
  SE-4 是**匹配层**问题（fail-closed，安全控制静默失效），后者优先级更高。

### SE-8 / TS-9 · 低频防御项（P2）

- SE-8：生产 CSP 显式声明。MV3 默认值已足够安全，此项是「把隐式依赖变显式」。
- TS-9：`i18n-dead-keys.mjs` 改为解析后的键提取。当前实现有假阴性可能，但无假阳性，
  作为门禁「宁漏勿误」是可接受的取舍。

## 6. 值得肯定、重构时不应破坏的设计

1. **搜索高亮的纯文本分段**（`core/search/SearchEngine.ts`）—— 从架构上消灭了高亮功能的 XSS 面。
2. **归组键保留 punycode、仅展示层转 Unicode**（`core/site/SiteResolver.ts`）—— 同形异义字无法造成误聚合，取舍正确。
3. **DNR host 权限走 optional + 用户手势内请求**（`wxt.config.ts`）—— 未开启功能时安装零全站权限警告，并有权限回收监听。
4. **导入的事务化回滚 + 坏数据隔离区**（`stores/dataStore.ts` / `platform/storage/DataRepository.ts`）—— 串行写 + 失败回滚，如实告知哪些分区回滚未完成；校验失败写入隔离区而非静默丢弃。
5. **诊断日志刻意排除浏览内容**（`platform/diagnostics.ts`）—— 只存时间戳 / 域 / 描述，不存标题与 URL。
6. **设计令牌守卫作为测试**（`tests/ui/design-tokens.test.ts`）—— 把设计规范变成会失败的断言，本轮正是它抓出了一个真实的产品缺陷（T-1）。
